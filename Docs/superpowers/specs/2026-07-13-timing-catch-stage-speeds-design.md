# 타이밍 캐치 스테이지별 속도 설정 설계

## 목표

타이밍 캐치 미니게임의 1~7 스테이지 게이지 이동 속도를 `TimingCatchConfig` 에셋 인스펙터에서 각각 독립적으로 조절할 수 있게 한다.

## 현재 구조

- `TimingCatchGameConfigSO`는 첫 스테이지 속도 `m_startGaugeSpeed`와 스테이지별 누적 증가량 `m_stageSpeedIncrease`만 직렬화한다.
- `TimingCatchGameModel`은 게임 시작 시 첫 속도를 적용하고, 스테이지 전환 시 증가량을 누적한다.
- 이 구조에서는 특정 스테이지만 빠르게 하거나 이전 스테이지보다 느리게 만드는 설정이 불가능하다.

## 승인된 설계

### 설정 데이터

`TimingCatchGameConfigSO`에 스테이지 순서와 일치하는 직렬화 배열 `m_stageGaugeSpeeds`를 둔다. 배열 인덱스 0은 1스테이지, 인덱스 6은 7스테이지를 의미한다.

기본값은 기존 누적 속도 동작과 동일하게 다음 값을 사용한다.

| 스테이지 | 게이지 속도 |
|---:|---:|
| 1 | 1.0 |
| 2 | 1.2 |
| 3 | 1.4 |
| 4 | 1.6 |
| 5 | 1.8 |
| 6 | 2.0 |
| 7 | 2.2 |

총 스테이지 수는 속도 배열 길이를 단일 기준으로 사용한다. 따라서 스테이지 수와 속도 항목 수가 서로 어긋나는 상태를 만들지 않는다.

### 모델 동작

`TimingCatchGameModel`은 누적 덧셈으로 속도를 계산하지 않는다.

- 게임 시작 시 1스테이지 속도를 적용한다.
- 판정 완료 후 다음 스테이지로 이동할 때 해당 스테이지 인덱스의 속도를 적용한다.
- 마지막 스테이지가 끝나면 기존과 동일하게 게임 진행 상태를 종료한다.
- 런타임 중 배열을 매 프레임 조회하거나 복사하지 않고 초기화 시 필요한 설정을 보관한다.

### 방어 규칙

- 속도 배열이 비어 있거나 누락된 경우 게임이 중단되지 않도록 안전한 기본 속도 1.0을 사용한다.
- 음수 속도는 0으로 보정한다.
- 스테이지 인덱스는 유효 범위로 제한하여 배열 범위 예외를 방지한다.
- 기존 인스펙터 설정 에셋은 새 배열 값으로 명시적으로 갱신하여 기존 체감 속도를 보존한다.

## 데이터 흐름

1. `TimingCatchConfig.asset`이 스테이지별 속도 배열을 직렬화한다.
2. `TimingCatchGameLifetimeScope`가 기존 방식대로 Config SO를 주입한다.
3. `TimingCatchGameModel`이 초기화 시 스테이지별 속도를 읽는다.
4. `ResetState`와 `AdvanceToNextStage`가 현재 스테이지에 맞는 속도를 선택한다.
5. `UpdateGauge`는 선택된 현재 속도로 게이지 위치만 갱신한다.

View와 ViewModel의 단방향 데이터 흐름 및 입력 처리는 변경하지 않는다.

## 변경 범위

- 수정: `Assets/_Game/Scripts/TimingCatch/Models/TimingCatchGameConfigSO.cs`
- 수정: `Assets/_Game/Scripts/TimingCatch/Models/TimingCatchGameModel.cs`
- 수정: `Assets/_Game/ScriptableObjects/TimingCatch/TimingCatchConfig.asset`
- 추가 또는 수정: 타이밍 캐치 모델 EditMode 테스트

## 검증

- 게임 시작 시 1스테이지 속도 1.0이 적용되는지 검증한다.
- 각 스테이지 전환 직후 설정된 속도가 정확히 적용되는지 검증한다.
- 기존 기본값 기준으로 7스테이지 속도가 2.2인지 검증한다.
- 빈 배열과 음수 속도 입력에서도 예외 없이 안전한 값이 적용되는지 검증한다.
- Unity 스크립트 컴파일 완료 후 콘솔 오류가 없는지 확인한다.
- Play Mode에서 인스펙터 값을 서로 다른 값으로 설정하고 각 스테이지 체감 속도가 독립적으로 변경되는지 확인한다.

## 제외 범위

- 스테이지별 판정 구간, 제한시간, 점수 설정 분리는 이번 작업에 포함하지 않는다.
- View, ViewModel, Presenter 및 버튼 이벤트 연결은 변경하지 않는다.
- 타이밍 캐치 외 다른 미니게임의 속도 설정은 변경하지 않는다.
